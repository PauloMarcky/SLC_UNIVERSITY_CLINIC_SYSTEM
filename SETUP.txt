============================================================================
SLC UNIVERSITY CLINIC SYSTEM - LOCAL SETUP
============================================================================

Plain-text copy of SETUP.md. Complete instructions to run the backend.

PREREQUISITES
  Node.js 24 or newer   https://nodejs.org
  MySQL 8.x             https://dev.mysql.com/downloads/mysql/
  Git                   https://git-scm.com

STEP 1 - CLONE
  git clone https://github.com/PauloMarcky/SLC_UNIVERSITY_CLINIC_SYSTEM.git
  cd SLC_UNIVERSITY_CLINIC_SYSTEM\backend

STEP 2 - INSTALL DEPENDENCIES
  npm install

STEP 3 - CONFIGURE .env
  Copy-Item .env.example .env
  notepad .env
  Set DB_HOST, DB_USER, DB_PASSWORD and DB_NAME for your local MySQL.

STEP 4 - CREATE THE DATABASE
  npm run migrate

  Creates the database if missing and applies every file in
  backend/db/migrations/ in order. Safe to re-run. The schema lives
  only in the migration files. Do NOT run schema.sql.

STEP 5 - OPTIONAL SAMPLE PATIENTS
  mysql -u root -p clinic < database/seed.sql

STEP 6 - DEFAULT STAFF ACCOUNTS
  npm run seed-users

  nurse1  / clinic-dev-2026   (Nurse)
  doctor1 / clinic-dev-2026   (Doctor)
  Change these before any real deployment.

STEP 7 - START
  npm start
  Open http://127.0.0.1:3000

DAILY WORKFLOW
  cd SLC_UNIVERSITY_CLINIC_SYSTEM\backend
  npm run migrate    (after pulling new migrations)
  npm run dev

MORE STAFF ACCOUNTS
  npm run create-user -- username nurse "Full Name"
  npm run create-user -- username doctor "Full Name"

TESTS
  npm test
  WARNING: tests truncate tables in the database named by DB_NAME. Use a
  separate test database. Run npm run seed-users afterwards.

TROUBLESHOOTING
  ER_ACCESS_DENIED_ERROR   Wrong DB_USER / DB_PASSWORD in .env.
  Missing MySQL environment variable(s)   .env missing or incomplete.
  EADDRINUSE 3000          Set PORT=3001 in .env.
  Non-default MySQL port   Set DB_PORT in .env.
  Migration failed         Fix the cause and re-run npm run migrate.

NOTES
  - Each teammate has their own local database.
  - Never commit .env.
  - Schema changes go in a NEW numbered migration, never an edit to an
    applied one.
